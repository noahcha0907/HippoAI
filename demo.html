Demo

From a failure to a repair report.

Explore the proposed workflow using a sycophancy scenario: a model changes its answer after a user claims medical expertise. This is an illustrative walkthrough, not a live model run.

Audit

Find the failure.

A correct answer changes when the user applies pressure. The first task is to investigate why.

Compare the model’s answer to a benchmark reference, then repeat the question with a misleading claim of expertise. Use those failures to guide inspection of the model’s weights.

Input
A model, a known failure, and its task specification.
Output
A candidate explanation and weights to investigate.
Question
Does the evidence point to a specific failure mechanism?
Repair

Make a targeted edit.

The proposed repair changes a small part of the model, with every change recorded.

Create a candidate weight edit aimed at the identified failure. Retain the original model and an edit log so the candidate can be compared, rejected, or reversed.

Input
The candidate mechanism and original model weights.
Output
An edited candidate and a record of its changes.
Question
Is the proposed change focused on the observed failure?
Validate

Test beyond the example.

Fixing the example is not enough. The edited model has to face independent tests.

Evaluate accuracy, susceptibility to misleading prompts, and performance on unaffected tasks. If the candidate fails the agreed checks, return to repair or reject it; do not promote it as a success.

Input
The original and edited models, plus held-out tests.
Output
A comparison of the target behavior and regressions.
Question
Does the evidence justify keeping the edit?
Report

Explain what changed.

Make the outcome legible to the people responsible for the workflow.

Describe the behaviors that improved or worsened, the potential clinical consequences, the edit history, and unresolved risks. The report supports review; it does not certify that a model is safe.

Input
Independent evaluation results and the edit history.
Output
A report for technical and clinical review.
Question
What is the remaining risk, and what still needs testing?

Audit stage selected

A failed check
means another look.

The validation stage is a decision point. A candidate that improves one example but introduces new failures does not count as a successful repair.

The intended loop is repair, test independently, then either revise the edit or report the evidence for review. A small edit still needs a thorough evaluation.

Repair⇄Validate

What a useful
report should explain.

Three views of the same error, informed by the clinical-impact framework.

Technical

How often did the error occur? Compare accuracy, false positives, false negatives, and changes on independent test sets.

Clinical context

What did the model miss or misclassify? Describe the finding or behavior, rather than reporting only a score.

Patient impact

Could the error delay a diagnosis, trigger extra review, or change treatment? Make the interpretation and uncertainty explicit.

What we still
need to prove.

The cited research shows that weight inspection can detect sycophancy in small models. It does not yet establish that weight editing repairs clinical sycophancy.

That is the hypothesis Hippo aims to test. This walkthrough contains no measured Hippo outcomes.
